# Run records on Codex and ChatGPT

Apply this host mapping together with `skills/run-records/SKILL.md` and `references/run-log-schema.md`; preserve their full procedure, optional settings, schema rules, report filing, idempotent keys, readback, and cleanup preconditions. Keep reports and workbooks private, external to this repository, public plugin, and shared Knowledge.

## Files and workbook execution

Codex uses its authorized filesystem and the installed helper at `${CAREER_ENGINE_ROOT}/skills/run-records/scripts/xlsx_log.py`. Workbook execution requires openpyxl; the repository's pinned requirements and trusted CI setup supply it before sandboxed review. If it is unavailable in a user's runtime, report the concrete limitation and preserve scratch; never claim a log write succeeded.

ChatGPT uses private Data Analysis files. Retrieve `runtime/xlsx_log.py.txt` from the kit or `skills/career-engine/runtime/xlsx_log.py.txt` from the plugin, materialize it as `xlsx_log.py` in the private sandbox, and check openpyxl before execution. If the helper is inaccessible, request that public runtime attachment; do not invent its contents. Import the helper and invoke its functions in Python; no shell, pandoc, computer filesystem, or Claude installation is required. For an existing log, the user supplies the private workbook; return and link the verified updated workbook for the user to save externally. A sandbox file does not persist to the user's computer or an earlier chat. If execution, dependency, or private workbook access is unavailable, report it and keep scratch. Never silently choose a different log destination.

For default creation use `cmd_init(path)`, which refuses overwrite. For upsert use `cmd_upsert(path, sheet, key_cols, row, create_default=...)`: permit creation only in default mode. In flexible mode inspect headers first with `cmd_headers(path)` and preserve the live sheet names, column order, existing values, and unmapped-column reporting. Never create, add, rename, or delete columns to force a match. After every write, reopen the actual workbook with openpyxl, find the rows by their configured keys, and compare all intended written values and counts with the persisted run records. A printed write response alone is not readback. Repeated writes update the same key, never append a duplicate run/application.

Notion uses actual available database read/query/property-write operations through `skills/database-notion/SKILL.md`; discover and inspect schemas before use. `notion-fetch` is a legacy example, not a literal tool on these hosts. Missing required operations keep the log write unverified and block cleanup. Never write the run log as page-body text.

## Filing, delivery, and cleanup

Resolve `agent_data_folder` per run-records §0: default `agent-data` next to `output_folder`, flat with no subdirectories. On ChatGPT, represent it in the private sandbox and provide downloads for the user to save to their chosen external folder. Write metrics directly there, using `references/run-metrics-host.md`; neither host runs Claude's token Stop hook. File the other prescribed reports and verify their nonzero contents at their final paths. Use those final paths in the composed message and artifact links.

Before deleting anything, read the run's state and flags, compose the delivery message, and retain the verified counts, flags, report paths, and evidence in private run records. Then file reports, write/read back the chosen log (or explicitly configured none), verify every role is terminal, and verify the actual DOCX for each track before removing that track's markdown. Preserve markdown when its DOCX failed. Interrupted runs delete nothing, even if filing and logging succeeded. Failed filing or log verification also retains scratch. Never delete a path outside this run or anything the run did not write; preserve the output folder and all filed reports. If birth time is unavailable or the run's start/write ownership cannot be established, keep the uncertain files and report the reason. Append the prescribed Records line; failures remain non-blocking for delivery and must be named.
